WINDOWS 11 HOME: PREPARACION HEADLESS DE UNA VM LIMPIA

PowerShell normal, bajo el mismo usuario que instalo VirtualBox:
  $Proyecto = '\\wsl.localhost\Ubuntu\home\sgalvez\zerocool\xmrig-personal-lab'
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action prepare

Descarga con curl.exe una ISO de evaluacion de Windows 11 Enterprise x64 es-ES,
mediante HTTPS desde la URL oficial de Microsoft fijada en el script. Guarda .part
y permite reanudar una descarga interrumpida. El SHA local es una huella de la
descarga; no se presenta como comparacion con un hash publicado por Microsoft.

Almacenamiento: %LOCALAPPDATA%\XmrigIsolatedAudit\VirtualBox
VM: Xmrig-Audit-Win11, 8 GB RAM, 4 CPU, VDI dinamico hasta 80 GB, UEFI/TPM2/SecureBoot.
Sin red, carpetas compartidas, portapapeles, drag and drop, USB, audio, VRDE ni 3D.
No cambia Defender ni la configuracion de WSL/Docker/Hyper-V del host.
No se instalan Guest Additions o servicios remotos. No se copia o ejecuta el minero.
El usuario local audituser y su clave aleatoria se usan solo en esta VM desechable.
La clave y los archivos unattended permanecen en la carpeta protegida por ACL del
usuario de Windows. No publicar guest-password.txt, unattended-prepare.log ni los
archivos de respuesta generados, pues contienen credenciales de esa VM.

El preparador solo crea una VM nueva, nunca borra o reinstala una existente.
Si falla tras crearla, conserva estado para diagnostico; no repite pasos de disco.
La instalacion desatendida arranca headless, pero su finalizacion se debe comprobar.
Una VM encendida no implica Windows instalado ni un resultado de auditoria.

Consultar estado / capturar pantalla / solicitar apagado ordenado:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action status
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action screenshot
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action stop

Capturas y estado se guardan en .runtime/vbox-audit dentro del proyecto; el asistente
puede leerlos. No contienen las credenciales. Tras apagar, -Action start reinicia la
VM solo si la preparacion termino y las comprobaciones de aislamiento pasan.

DESPUES DE VER EL ESCRITORIO DE WINDOWS
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action setup-control

Solicita apagado ACPI y espera hasta 120 s. Nunca fuerza apagado ni reinicia en
caliente. Si Windows no responde, apagarlo desde Inicio y repetir. Preserva una
instantanea offline antes de sustituir el DVD de instalacion por Guest Additions.
La instantanea se registra por UUID y se conserva al repetir setup-control.
Despues arranca headless con el disco primero. No instala aun las Guest Additions.

Dentro de la VM, abrir el DVD de VirtualBox Guest Additions, ejecutar
VBoxWindowsAdditions.exe como administrador, completar instalacion y reiniciar
el invitado. Esto instala el canal VBoxService, no habilita red ni carpetas
compartidas. El instalador se ejecuta en el invitado, nunca en el anfitrion.

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action guest-status

Usa guestcontrol y la clave temporal ya existente sin imprimirla. Ejecuta solo
una consulta fija sobre identidad, privilegio administrativo efectivo, servicio,
version de Windows y presencia de red. Guarda .runtime/vbox-audit/guest-status.json.
Si administrator=false, el canal existe pero no acredita elevacion. No se cambia
UAC ni Defender. No se inicia ninguna muestra mediante estas acciones.

Si el canal ordinario informa administrator=false, se puede comprobar un proceso
elevado separado con el consentimiento UAC normal del invitado:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$Proyecto\audit-isolated\vbox-windows.ps1" -Action guest-admin-status
Mantener abierta la ventana de la VM con audituser conectado y aceptar alli el
aviso de PowerShell. Solo se ejecuta la consulta fija de estado; no se instala
un servicio, tarea programada ni acceso administrativo permanente. Guarda
.runtime/vbox-audit/guest-admin-status.json. El canal normal no cambia de privilegio.
Si no aparece el aviso UAC o vence el plazo, revisar la ventana antes de repetir.
El progreso de carga de modulos se silencia para evitar CLIXML en la consola.

PRUEBA DE CONTROL ADMINISTRATIVO
guest-control-proof -ProofId <32 caracteres hexadecimales> solicita UAC dentro
del invitado y realiza una operacion reversible: crear una clave HKLM con nombre
unico, escribir el identificador, leerlo y eliminar la clave en finally. Rechaza
claves preexistentes y solo opera si el proceso esta elevado y la VM sin red.
Guarda control-proof-<id>.json con la identidad y los resultados de lectura y
limpieza. La prueba acredita esa operacion; no representa acceso permanente ni
certifica inocuidad del minero. No modifica UAC, Defender ni claves ajenas.

notify-telegram.py envia hitos y solicitudes al chat privado ya vinculado,
usando la configuracion local sin imprimir el token. Registra los IDs de entrega
en .runtime/vbox-audit/telegram-actions.jsonl. Su uso para reportar esta auditoria
y solicitar acciones en el host fue autorizado expresamente por el usuario.
El umbral actual es WARN: avances y resultados satisfactorios INFO no se envian.
Usar --level WARN para problemas que requieran atencion o intervenciones
necesarias; ERROR para fallos que impidan continuar. Las respuestas a comandos
del propietario y a su orden de parada siguen habilitadas.

PARADA DESDE TELEGRAM
El bot local acepta /detener, /stop o "deten todo" (con o sin tilde), solo desde
la cuenta privada vinculada. Guarda stop-request.json antes de responder. El
script rechaza nuevas acciones de trabajo mientras exista esa solicitud.
pause-work solicita controlvm pause solo con VMState=running y verifica el
resultado. Estados ocupados, como livesnapshotting, se reportan pendientes y
el bot reintenta; nunca usa poweroff. El bot permanece escuchando y conserva
la parada tras reiniciar. No hay reanudacion automatica ni comandos libres.
La senal tambien se consulta por el asistente antes de nuevas operaciones;
no equivale a interrumpir de forma nativa el turno de chat ni operaciones
del host ya iniciadas. No detener el bot si se necesita mantener este canal.

LIMITES
Este script prepara el Windows invitado; NO implementa todavia la captura Procmon
para VirtualBox. run-inside.ps1 sigue restringido a Windows Sandbox. No cambiar
su comprobacion de usuario para ejecutarlo en el host o forzarlo en esta VM.
Despues de comprobar Guest Additions y privilegios, falta preparar un medio de
entrada de auditoria, con validacion de hash y un observador especifico para VM.
La prueba offline no demuestra seguridad del minero con pool/GPU reales.
