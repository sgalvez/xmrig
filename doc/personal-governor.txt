Personal Ravencoin GPU governor (sgalvez fork)

This is a GPL-3.0-or-later derivative of XMRig 6.26.0. The original
license, copyrights and donation attribution are retained. Personal changes
also preserve verified TLS and Windows system DLL loading. Donation is disabled in the personal build.

Opt in on each OpenCL KAWPOW thread profile with "gpu-duty-percent": 25.
0 or omission preserves upstream scheduling. Accepted values: integer 5..100.
Governed profiles require intensity <= 65536; mixed enabled/disabled
profiles on the same GPU are rejected. Use one thread, worksize 128 and intensity 65536 for the initial RX 9070 XT
trial. GPU index must be selected from the local inventory; it is not portable.
The percentage limits host-observed GPU batch duty, not clocks, wattage, fan
speed, or a guaranteed fraction of hashrate. Other applications can heat the GPU.

Both DAG batches (16384 nodes) and search batches wait before their next GPU
submission. Results are returned without waiting for the following cooldown.
Controllers are shared by PCI identity and serialize workers on one device.
Different devices remain independent. A new DAG is marked valid only after
all batches complete. Stop is checked at most every 50 ms while waiting.

Telemetry: gpu-health JSON v1 identifies PCI address, OpenCL index, polling
time, source, edge_c, hotspot_c, memory_c, power_w and fan_rpm. Unsupported
values are null. polled_ms is a monotonic host poll time, not a driver-provided
hardware measurement timestamp. Unchanged measurements can be legitimate;
this cannot detect a driver that returns successful but frozen measurements.
Windows ADL PMLog provides the identified sensors. Overdrive7's old numeric
temperature selector remains unclassified. The governor requires identified
edge and hotspot: unsupported drivers, Linux's old sysfs reader and disabled
ADL fail closed when duty control is enabled. They retain upstream behavior
when it is disabled. Memory is optional until observed; losing it then faults.

Local user-selected limits (C), not AMD manufacturer ratings:
               reduce duty    pause >=    resume <=
  GPU edge          60          80          60
  hotspot           65          80          60
  memory            65          80          60
Any available sensor at 80 pauses submissions. All available sensors must
reach 60 or below to resume, starting at 5% duty. Cooling never expires.
Reduction: 5 percentage points per second, minimum 5%. Recovery: 1 point
per 5 seconds up to the configured ceiling. Missing, implausible or stale
(>2 s) samples latch a fault until process restart. Thermal pauses do not.
gpu-governor JSON records state, sensor reason, phase, exact sample and
actual duty (zero while cooling). After waiting, discard stale search jobs.

The foreground supervisor counts 300 non-cooling seconds for its trial.
Ctrl+C writes a unique cancellation marker, which is checked both before
launching and while supervising the owned miner. A thermal pause is shown
in the status panel and does not close the application.

The native controller cannot interrupt a hung driver call or a kernel already
in flight. Keep the independent process supervisor and hardware thermal
protection. An exit from a worker is not necessarily an exit from XMRig;
the supervisor must stop the process when it sees a governor fault. This is
not a claim that unattended mining or this specific GPU is validated.

Tests: g++ -std=c++11 -Wall -Wextra -Werror -Isrc

       /tmp/governor-test
Real-device acceptance still requires a bounded trial, comparison with AMD
Adrenalin edge/hotspot readings, cooling/recovery observation and own pool
shares. A new executable hash requires a new scan and mining validation.

Load policy v5: the supervisor reads gpu_duty_percent from local mining.json
(default 25, integer 5..100; zero is forbidden by the supervisor). A new load
requires a new pool-validated trial. Active duty drops by five points per second
when any available sensor reaches 75 C and recovers one point per five seconds
at <=70 C. Emergency halt remains 80 C with resume only at <=60 C on all
available sensors. These are local policy limits, not manufacturer guarantees.
